# Power mapping

## Decision map (after Grove's decision frame)

Settle the frame before debating the substance.

| Question | Answer | Evidence |
|---|---|---|
| What exactly is being decided? | | |
| When must it be decided? What forces it? | | |
| Who decides? | | |
| Who must be consulted? | | |
| Who can ratify or veto? | | |
| Who implements, and can quietly fail to? | | |
| Who needs to be informed afterward? | | |

If nobody can answer "who decides," that's the first problem to solve, and often the whole problem.

## Influence map (after Watkins)

1. List the decisions the initiative needs and who formally decides each.
2. For each stakeholder: current position (support, oppose, persuadable), interests, alternatives, and who influences them.
3. Identify the winning coalition (enough for a yes) and any blocking coalition (enough to stop it).
4. Choose a technique per person: consult them; reframe the proposal; reshape the choice; bring in an opinion leader; ask for an incremental step.
5. Sequence: opinion leaders first, then persuadables; meet opponents' interests where you can.
6. Name the action-forcing event that ends deliberation.

## Sources of power

Map these for each key stakeholder, from evidence.

| Source | What to look for |
|---|---|
| Formal authority | Decision rights, budget, headcount, review-writing |
| Resource control | Engineers, data, compute, customer access, budget |
| Information | Who knows things first; who sits in the forums where things are decided |
| Expertise | Whose judgment is deferred to, on what |
| Network position | Who bridges groups that don't otherwise talk |
| Sponsorship | Who the CEO or a key executive backs |
| Track record | Recent wins that buy credibility |
| Unit power | Whether their unit is on the company's critical path and gaining budget |

## Reading what the system rewards

- Who got promoted in the last year, and what did they visibly do?
- How were the last two cross-team conflicts resolved: by process, by escalation, by whoever pushed hardest?
- Do exceptions (off-cycle raises, special projects) go to people who ask loudly?
- Are org design decisions explained and consistent, or opaque?

If the system rewards lobbying, expect lobbying from others and read it as incentive. The user still stays inside the legitimacy filter, and can make their merit case louder and more explicit within the process.

## Reorg and power-shift analysis

When structure changes:
1. Who gained scope, budget, or reporting lines? Who lost?
2. Whose priorities does the new structure encode?
3. Which of the user's sponsors gained or lost standing?
4. What unowned problems did the change create? (Candidates for `scope-expansion`.)
5. Which relationships need renegotiating, and in what order?
6. What is still undecided, and when does it get decided?

Record facts as evidence entries (type `reorg`); keep interpretations as hypotheses.
